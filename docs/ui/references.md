## Observed limits to preserve in the baseline

- Logical widgets/panes are not always separate components. Refactoring source
  does not automatically mean a UI entity or user contract changed.
- Prepared runs persist but are excluded from the current Agents list; do not
  document a prepared-launch browser/list page that is not implemented.
- Relationship/ticket IDs are displayed text, not existing link destinations.
- Selecting a filter can leave a previously selected detail visible. There is no
  dedicated zero-search-results widget/message in the current list.
- Settings has no unsaved-changes guard, and choosing Create a skill does not
  clear previously populated skill fields. The item priority input is a draft
  rather than a faithful prefilled view of the stored override.
- Modal roles do not prove focus trapping, focus restoration, Escape handling,
  keyboard completeness or screen-reader acceptance. Overlay mutual exclusion and
  request-to-request answer-draft reset also need deliberate verification.
- Notification configuration and visible attention indicators do not demonstrate
  real host subscriptions, callback receipt or a completed soak. Those remain
  governed by [acceptance](../acceptance.md).

These are documentation findings and coverage limits. This task does not silently
change product behavior to resolve them or claim they are new desired behavior.
